# DevOps Assessment Implementation Plan

**Goal:** resolver los requisitos del PDF con entrega reproducible y verificable.
**Architecture:** Kong -> FastAPI replicado -> Redis; Kubernetes y Compose.
**Tech Stack:** Python, pytest, Docker, Kong, Redis, Kubernetes, GitHub Actions.
**Spec:** docs/design.md.

## Restricciones globales

Ruta /DevOps y header X-JWT-KWY literales. Rama productiva master. JWT de un uso.
Mínimo dos nodos y dos réplicas. Cobertura interna objetivo 95% (no impuesto por PDF).
Secretos fuera de Git. Sin envío de mensajes reales.

## 1. Contrato REST y seguridad
- [ ] Crear tests/test_api.py con respuestas, validación, auth, replay y disponibilidad.
- [ ] Ejecutar `.venv/Scripts/python -m pytest` y observar fallos antes de implementar.
- [ ] Implementar src/devops_service/{app,security,settings,replay}.py.
- [ ] Ejecutar pytest con cobertura y corregir únicamente contra contrato.
- [ ] Versionar pruebas y servicio en commits separados de TDD.

## 2. Ejecución reproducible
- [ ] Crear Dockerfile, compose.yaml y scripts de preparación/emisión de tokens.
- [ ] Probar Kong + dos backends + Redis real; rechazos y replay concurrente.
- [ ] Fijar dependencias resueltas y ejecutar lint, Bandit y pip-audit.

## 3. Infraestructura y CI/CD
- [ ] Crear manifiestos Kubernetes con probes, HPA, PDB y separación en dos nodos.
- [ ] Crear scripts de despliegue y cluster kind de dos workers.
- [ ] Crear pipeline con build, test, integración, publicación por digest y deploy.
- [ ] Validar configuración renderizada y realizar comprobaciones disponibles.

## 4. Entrega
- [ ] Documentar instalación, evaluación, emisión JWT, escalado, rollback y evidencias.
- [ ] Revisar cambios y ejecutar verificaciones finales.
- [ ] Publicar/desplegar si existe destino autorizado; registrar limitaciones reales.
